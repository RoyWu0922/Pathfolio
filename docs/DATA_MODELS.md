# Data models

Canonical JSON. Python Pydantic models must match these fields. TypeScript types are generated by hand in MVP (no openapi-codegen required, but `/openapi.json` should exist).

Ids are `ulid` or `uuid4`. Timestamps ISO-8601 UTC.

## Profile

```json
{
  "id": "uuid",
  "display_name": "Alex Tan",
  "contact": { "email": null, "phone": null, "linkedin": null },
  "school": "City University of Hong Kong",
  "degree": "BBA",
  "field": "Business Analysis",
  "grad_year": 2026,
  "location_preference": ["Hong Kong"],
  "skills": ["excel", "sql", "python", "tableau"],
  "languages": ["English", "Cantonese", "Mandarin"],
  "experiences": [
    {
      "id": "uuid",
      "title": "Data Intern",
      "org": "Helix Studio",
      "start": "2025-05",
      "end": null,
      "current": true,
      "bullets": ["Built weekly dashboards tracking activation and retention."],
      "tags": ["analytics"]
    }
  ],
  "education": [
    {
      "school": "City University of Hong Kong",
      "degree": "BBA",
      "field": "Business Analysis",
      "end_year": 2026
    }
  ],
  "constraints": { "no_industries": [], "needs_sponsorship": false }
}
```

`display_name` and `contact` never leave the browser toward the LLM. The API may store them in session memory for the report.

  "positioning": "CityU business-analysis graduate who has already shipped reporting that squads used.",

    "skill_overlap": 0.40,
    "nace_coverage": 0.55,
    "evidence_transfer": 0.67,

  },
  "matched_skills": ["sql", "python", "excel"],
  "missing_skills": ["tableau", "ab test"],

`rationale` and `positioning` may come from the LLM. Numeric fields must come from `packages/scoring`.

## Diff suggestion

```json
{
  "id": "uuid",
  "experience_id": "uuid",
  "before": "Built weekly dashboards tracking activation and retention.",
  "after": "Built weekly dashboards tracking activation and retention for three squads, informing two roadmap decisions per quarter.",
  "reason": "Adds scope and a decision outcome; still uses only facts in the profile.",
  "status": "pending"
}
```

`status`: `pending | accepted | dismissed | edited`. If `edited`, extra field `user_text`.

**Fact check:** `after` must not introduce employers, tools, or metrics absent from the profile unless the user typed them. If the LLM adds a metric, drop the suggestion and set `insufficient_evidence: true`.

## Strategy

```json
{
  "track_id": "analytics",
  "questions": [
    {
      "id": "uuid",
      "text": "Walk us through a time messy data changed a decision.",
      "kind": "behavioural",
      "competency": "critical_thinking",
      "why_asked": "Analyst roles live in incomplete data; they want process, not a perfect warehouse."
    }
  ],
  "plan7": [
    { "day": 1, "title": "Fix resume six-point misses", "done": false }
  ]
}
```

`kind`: `behavioural | technical | motivational | case`.

## Session

```json
{
  "id": "uuid",
  "created_at": "...",
  "profile": {},
  "tracks": [],
  "scans": {},
  "suggestions": {},
  "stories": {},
  "strategies": {},
  "accepted_only_in_report": true
}
```

Report renderer includes **accepted** suggestions and stories only. Pending drafts stay in the workspace.
